# 代码审查与清理

## 动作模式

| 模式 | 触发词 | 做什么 |
|------|--------|--------|
| **快速审查** | "检查一下"、"review"（默认） | 构建 + 测试 + 报告基础问题 |
| **深度审查** | "深度 review"、"仔细看看" | + 命名职责 + 依赖方向 + API 表面积 |
| **清理** | "清理代码"、"整理一下"、"格式化" | 直接修复格式问题 |

## 范围识别（三级，所有模式共享）

- **当前对话（默认）**：无特殊限定词 → 从对话上下文收集本次 Edit/Write 过的文件
- **Git 修改**："git 修改"、"未提交的"、"工作区修改" → git status 所有修改文件
- **全量**："整个项目"、"全项目"、"全量"、"所有代码" → 整个项目

## 审查内容

### 快速审查
- 构建验证（dotnet build）
- 测试运行（dotnet test --filter "Category!=Performance&Category!=Slow"）
- 基础规范检查

### 深度审查（在快速基础上增加）
- 代码风格详细检查（按 coding-standards.md）
- 命名-职责一致性：类名/方法名是否准确反映其实际职责
- 依赖方向检查：是否违反 core-patterns.md 中的架构分层约束
- API 表面积检查：public 暴露是否合理，是否有应为 internal 的类型
- 测试覆盖分析
- 真源一致性检查

### 清理模式
直接修复以下问题（不报告，直接改）：
1. 未使用的 using 声明
2. 重复的 using 声明
3. using 排序（System 优先，按字母序）
4. 文件末尾空行规范
5. 行尾空格

**排除目录**：`**/obj/**`、`**/bin/**`、`**/*.g.cs`

## 执行流程

### 审查模式（快速/深度）

1. **确定范围**
   - 当前对话：回溯对话上下文，收集所有 Edit/Write 操作涉及的文件路径
   - Git 修改：执行 `git status` 获取修改文件列表
   - 全量：扫描整个项目

2. **深度审查前确认**
   如果是深度审查，先告知用户检查项和文件数量

3. **执行审查**（按真源）
   - `docs/02-guides/coding-standards.md` - 代码风格
   - `docs/01-architecture/core-patterns.md` - 架构、性能
   - `docs/testing-guidelines.md` - 测试要求

4. **输出摘要**

快速审查：
```
## 审查摘要

**模式**：[范围] + 快速
**范围**：N 个文件

| 检查项 | 状态 |
|--------|------|
| 构建验证 | ✅ / ❌ |
| 测试运行 | ✅ N通过 / ❌ N失败 |
| 基础规范 | ✅ / ⚠️ N个问题 |
```

深度审查：
```
## 审查摘要

**模式**：[范围] + 深度
**范围**：N 个文件

| 检查项 | 状态 |
|--------|------|
| 构建验证 | ✅ / ❌ |
| 测试运行 | ✅ N通过 / ❌ N失败 |
| 代码风格 | ✅ / ⚠️ N个问题 |
| 命名-职责 | ✅ / ⚠️ N个问题 |
| 依赖方向 | ✅ / ⚠️ N个问题 |
| API 表面积 | ✅ / ⚠️ N个问题 |
| 测试覆盖 | ✅ / ⚠️ |
| 真源一致性 | ✅ / ❌ |

### 问题详情（如有）
...
```

### 清理模式

1. 确定范围（同上）
2. 扫描目标 `.cs` 文件
3. 直接修复问题
4. 输出摘要：

```
## 清理摘要

**范围**：N 个文件
**修复**：M 个文件

| 文件 | 修复项 |
|------|--------|
| XxxSystem.cs | 删除 2 个未使用 using |
| YyyService.cs | 删除尾随空格 |
```
