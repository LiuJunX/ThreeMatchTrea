# 关卡设计框架

<!-- SOURCE_OF_TRUTH: level-design-framework -->

本文档是关卡设计的核心框架，所有关卡制作（手工或 AI 生产）必须遵循。

技术实现细节见 `docs/03-design/`，本文档聚焦**设计哲学和方法论**。

---

## 1. 设计哲学

### 1.1 核心原则

1. **从心理学原理推导机制，不从竞品功能清单反推**
2. **体验即教学**：不用弹窗引导，通过关卡结构让玩家自然学会机制
3. **低地板高天花板**：新手能过、老手有追求，同一关产生不同层次的体验
4. **前期体验密度不低于中后期**：前 20 关是试镜，不是教学
5. **认知负荷通过单关元素数量控制**，不通过时间线限制元素可用性

### 1.2 设计三问

每一关设计前问自己：

1. **这关的核心矛盾是什么？**（不是"用了什么元素"，而是"玩家面临什么抉择"）
2. **节奏弧线是什么？**（开局→中盘→收尾各是什么体验？有没有转折点？）
3. **新手和老手分别会怎么玩？**（两种人都觉得好玩吗？）

### 1.3 关于"新鲜感"

新鲜感不来自"没见过的元素"，而来自**"没预料到的局面"**。

- 错误做法：靠不断放出新元素维持新鲜感（内容消耗型，不可持续）
- 正确做法：用有限元素的组合制造无限的局面变化（组合爆炸型）

国际象棋所有棋子从第一局就全部存在，新鲜感来自棋局的组合，不是"第 50 局解锁新棋子"。

## 2. 心理学基础

### 2.1 多巴胺与不确定性

多巴胺释放量由**"预期与现实的差距"**决定（Wolfram Schultz），不是由奖励本身决定。

对关卡设计的启示：
- 完全在预期内的结果 → 无反应
- 意外的好结果 → 多巴胺飙升
- 静态关卡的问题：确定性单调递减 → 兴奋感单调递减

### 2.2 棋盘中的三种不确定性

| 类型 | 定义 | 设计手段 |
|------|------|---------|
| **信息不确定** | 棋盘上有我看不到的东西 | 障碍内容物（Box 里藏东西）、多层障碍遮挡 |
| **生成不确定** | 下一个掉下来的是什么 | Spawner 权重变化、颜色分布突变 |
| **后果不确定** | 我的操作会触发什么连锁 | cascade、炸弹引爆、死亡效果 |

好的关卡应该同时激活至少两种不确定性。

### 2.3 心流的挑战-技能平衡

静态关卡的问题：随着障碍减少，挑战低于技能 → 跌出心流进入无聊区。

解决方案：**通过 board 设计制造自然的阶段感**，在确定性即将坍缩时注入新的复杂性。

### 2.4 蔡格尼克效应

人对未完成的任务有强烈的心理挂念。利用方式：当玩家刚完成一个阶段（心理线程关闭），立刻展开新的挑战（重新激活）。

## 3. 阶段感设计（伪波次系统）

### 3.1 为什么需要阶段感

单阶段关卡 = "看到全貌 → 逐步清除"，体验是单调递减的。

阶段感关卡 = "建立预期 → 打破预期 → 重建掌控"，对应三幕结构的叙事本能。

| 阶段 | 玩家体验 | 心理状态 |
|------|---------|---------|
| **建立**（阶段 1）| 观察棋盘，制定策略 | 掌控感 |
| **打破**（阶段 2 展开）| 棋盘结构变化，新局面 | 惊喜/紧张 |
| **重建**（适应并通关）| 用更高策略应对 | 成就感 |

### 3.2 体验模式库

在不增加新机制的前提下，用 board 设计制造阶段感。详见 `level-design/patterns/`：

| 模式 | 核心体验 | 详情 |
|------|---------|------|
| [决堤](patterns/dam-break.md) | 空间释放 + cascade 狂欢 | 障碍行破裂 → tile 涌入空白区 |
| [引爆](patterns/chain-detonation.md) | agency 放大感 | 小操作触发大爆炸 |
| [层层揭开](patterns/peeling.md) | 渐进推进感 | 从一端逐层突破覆盖层 |
| [内外翻转](patterns/inside-out.md) | 空间叙事感 | 从外围打开封闭结构 |
| [自教学](patterns/self-teaching.md) | 体验即教学 | 通过关卡结构引导学习 |
| [Boss 关](patterns/boss-level.md) | 综合检验 + 仪式感 | 多元素组合的节奏波峰 |
| [双目标](patterns/dual-objective.md) | 注意力分配 | 同向/中立/冲突三种组合 |

这些模式可以自由组合——比如决堤 + 引爆、层层揭开 + Boss。

### 3.3 原语实现状态

| 原语 | 描述 | 状态 |
|------|------|------|
| **障碍内容物** | Cupboard 释放 Plate、Mailbox 释放 Envelope | ✅ 已实现 |
| **Spawner 激活/停用** | SpawnerPhaseConfig + obstacleCleared 触发器实现空间展开 | ✅ 已实现 |
| **Spawner 权重软切换** | 支持 per-Spawner 权重自定义（WeightedDefaultCondition），但尚无 phase 级权重切换 | ⚠️ 部分实现 |
| **新障碍品种** | 有固定死亡效果的新障碍（如 TreasureBox→释放炸弹、PandoraBox→喷 Honey） | ❌ 待建 |

原则：同种障碍行为恒定，差异通过"品种"体现，不做同一障碍可配置不同行为。

## 4. 认知负荷管理

### 4.1 元素认知成本分级

元素分布在三套枚举中：GroundType（地面层）、CoverType（覆盖层）、ObstacleType（障碍层）。

| 认知成本 | 元素 | 层 | 原因 |
|---------|------|---|------|
| 低 | Ice | Ground | 视觉自解释，踩碎即可 |
| 低 | Box、Stone | Obstacle | 破坏逻辑直观（打就行） |
| 低 | Grass、Leaves | Ground | 死亡效果产物，自动出现 |
| 低 | 预置炸弹 | Tile | 视觉自解释 |
| 中 | Cage、Chain、Frost | Cover | 需要理解"它限制了什么" |
| 中 | Honey、Bubble | Cover | 需要理解扩散/移动机制 |
| 中 | Bush、Safe、Owl | Obstacle | 需要理解免疫规则（Safe/Owl 免疫 Match） |
| 中 | Cupboard、Mailbox | Obstacle | 需要理解释放/生成机制 |
| 高 | MagicHat | Obstacle | 累计触发 + 生成特殊 tile |
| 高 | PotionBottle | Obstacle | 子瓶 bitmask + 颜色匹配 |
| 高 | ColorBox、Curtain | Obstacle | 需要理解颜色条件性交互规则 |

### 4.2 排列约束

- **单关新概念 <= 1**：每关最多出现一个玩家之前没见过的元素
- **前 5 关**：只用低认知成本元素
- **6-20 关**：可引入中认知成本元素
- **20 关之后**：可引入高认知成本元素 + 多元素组合
- **任何位置**：已出现过的元素可自由组合

这比"每 15 关解锁一个"灵活，但仍然保证玩家不被认知负荷淹没。

### 4.3 自教学关卡设计

新机制首次出场时，通过关卡结构引导玩家，不通过弹窗：

- **数量最少**：首次只放 1-2 个新元素实例
- **位置显眼**：放在棋盘中心或必经路径
- **目标宽松**：步数充裕，允许试错
- **周围简单**：新元素附近不放其他复杂元素
- **结果即时**：操作新元素后立刻看到明显效果

## 5. 前期关卡策略

### 5.1 前 20 关的任务

前 20 关不是教学，是**试镜**。玩家在问："这个游戏和我玩过的有什么不同？"

2026 年的三消用户画像：
- 大多数已玩过至少一款三消，基础机制不需要教
- 前 20 关的平淡教学 = "这游戏不把我当回事"
- 你有 10-15 关的时间证明"这个游戏值得玩下去"

### 5.2 同一关，不同体验层

不分类玩家，让关卡自适应：

| 维度 | 设计要求 |
|------|---------|
| **低地板** | 即使随便玩也能通关（步数宽裕、预置炸弹兜底） |
| **高天花板** | 精准操作显著减少步数（多出的步数 → 高星级） |
| **自然引导** | 关卡结构让新手"不得不"以接近正确的方式玩 |

星级系统是天然的自适应机制：新手 1 星通关，老手 3 星通关，不需要给不同关卡。

### 5.3 不做前期玩家分类

原因：三消结果方差太大（cascade 随机 ~50%，Spawner ~20%，玩家决策 ~30%），1-3 关的样本量下信号不足。误分类代价不对称——把老手判成新手导致流失的代价远高于反之。

如果需要微调，最安全的方式：只调步数余量（±2 步），基于 5 关累积数据，不改变关卡内容。

## 6. 难度调节

### 6.1 调节优先级

| 优先级 | 手段 | 灵敏度 | 风险 |
|--------|------|--------|------|
| 1（首选）| 步数 ±1~2 | ±3-5% 胜率 | 极低 |
| 2 | 颜色数 ±1 | 显著 | 低 |
| 3 | 目标数量 | 中等 | 中 |
| 4 | 障碍数量/HP | 中等 | 中 |
| 5（最后）| 棋盘形状 | 最大 | 高 |

详见 `docs/03-design/level-knowledge/core/difficulty-levers.md`

### 6.2 分析管线注意事项

- 分析服务用纯随机 SpawnModel，TargetDifficulty 不影响分析结果
- 分析胜率是"纯随机玩家"的下界，粗略估计：分析 70% ≈ 实际 85%+
- `grid: null` 会导致非 8x8 关卡分析崩溃，必须提供显式 Grid 数组
- Cage 不能作为胜利目标条件（random 玩家 0% 胜率）
- Ice 目标数 10→11 有 ~15% 胜率跳变（容错从 5 块降到 4 块是质变）

## 7. 协作模式

### 7.1 分工

| 阶段 | 方式 |
|------|------|
| **前期（L1-30）** | 用户定设计意图，AI 实现和验证，逐关手工打磨 |
| **中后期** | AI 基于积累的设计原则自主生产，用户质检纠偏 |
| **持续** | AI 在批量生产中识别有价值的新组合模式，主动标记和复用 |

### 7.2 单关制作流程

```
1. 明确设计意图（核心矛盾、节奏弧线、体验目标）
2. 制作 LevelConfig JSON
3. 分析管线验证（胜率、死锁率）
4. 调参迭代（优先调步数）
5. 沉淀设计记录到 level-design/levels/LXXX.md
```

### 7.3 文档结构

```
level-design/                              ← 设计方法论（本目录）
├── framework.md                           ← 本文件：核心框架
├── patterns/                              ← 体验模式库
│   ├── dam-break.md, chain-detonation.md
│   ├── peeling.md, inside-out.md
│   ├── self-teaching.md, boss-level.md
│   └── dual-objective.md
└── levels/                                ← 单关设计记录

docs/03-design/level-knowledge/            ← 元素技术参考（机制细节）
├── core/                                  ← 匹配、掉落、炸弹、难度调节
└── elements/                              ← 各元素的属性、放置原则、组合建议
```

两个目录职责不同：`level-design/` = 怎么做好关卡，`level-knowledge/` = 东西怎么运作。

## 8. 做关必知（踩坑经验）

| 经验 | 详情 |
|------|------|
| grid:null 崩溃 | 非 8x8 关卡必须提供显式 Grid 数组 |
| Cage 目标 0% | Cage 只能作为观察元素，不能作为胜利条件 |
| Ice 跳变 | Ice 目标 10→11 有 ~15% 胜率断崖 |
| 步数精度 | ±1 步 ≈ ±3-5% 胜率，是最精准的调参旋钮 |
| Cage 中部死锁 | 4 Cage 交错放中间 → 14.8% 死锁；底部放 → 正常 |
| Spawner 设计 | 只帮不害，seed 粗调 + SpawnModel 安全网（80/20） |
