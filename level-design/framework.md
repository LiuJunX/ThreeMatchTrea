# 关卡设计框架

<!-- SOURCE_OF_TRUTH: level-design-framework -->

本文档是关卡设计的核心框架，所有关卡制作（手工或 AI 生产）必须遵循。

技术实现细节见 `docs/03-design/`，本文档聚焦**设计哲学和方法论**。

---

## 0. 第一原则

> **让玩家觉得是自己赢的。**

不是系统帮他赢的，不是运气让他赢的，不是付费买的胜利——是"我想到了，我做到了，我赢了"。

本文档所有设计原则均由此推导：
- 操作有意义 → 低地板高天花板、只帮不害、强控红线
- 发现是自己的 → 体验即教学、认知负荷管理、不确定性设计
- 失败是自己的 → 设计者契约、信任银行
- "赢"要有重量 → 阶段感、前期高密度、预期违背

当任何设计决策产生矛盾时，回到这一条判断。

## 1. 设计哲学

### 1.1 核心原则

1. **从心理学原理推导机制，不从竞品功能清单反推**
2. **体验即教学**：不用弹窗引导，通过关卡结构让玩家自然学会机制
3. **低地板高天花板**：新手能过、老手有追求，同一关产生不同层次的体验
4. **前期体验密度不低于中后期**：前 20 关是试镜，不是教学
5. **认知负荷通过单关元素数量控制**，不通过时间线限制元素可用性
6. **强控不能让玩家学到的东西失效**：动态难度调节可以抬高地板（帮助弱玩家），但不能压低天花板（削弱强玩家）。玩家通过游玩积累的知识和技能（如"操作底部 cascade 更长"、"主动制造炸弹组合"）必须始终有效。减小体验方差是合理的，但强制惜败或覆盖核心游戏规律是禁止的

### 1.2 核心赌注

以下是本项目最根本的设计决策。它决定了整个游戏的走向，尤其是前期体验。一旦改变，几乎所有关卡设计都要重来。

> **我们信任玩家。从第 1 关起就做真正的关卡，不做教学。**

具体含义：

1. **不做新手引导系统**。没有弹窗教学、没有强制箭头、没有"点击这里"。关卡结构本身就是教学。
2. **不做速通教学关**。L001 不是"只有 1 个有效 swap"的脚本化体验，而是一个有真正设计的关卡。
3. **高天花板技巧不教**。炸弹合成（4 连）、炸弹+炸弹交换等进阶技巧，通过自然游玩中频繁出现来让玩家自己发现。发现本身就是奖励。
4. **为体验设计，不为留存设计**。留存是好体验的自然结果。如果体验好但留存差，问题在体验，不在留存策略。

**我们在赌什么：**

- 赌 2026 年的三消用户大多玩过至少一款三消，不需要从零教起
- 赌玩家有能力自己发现规则，而这个发现过程本身比被教会更有价值（自我效能感 §2.5）
- 赌尊重玩家智商（设计者契约 §2.6）比防止极少数新手流失更重要

**风险：**

- 完全没玩过三消的纯新手可能在前几关懵几秒。缓解方案：空闲提示系统（N 秒无操作后高亮一个可消组合），这是 UI 层的轻提示，不是关卡层的强制引导。
- 少数玩家可能很晚才发现炸弹合成。缓解方案：确保自然游玩中 4 连频繁发生（4 色 + cascade），效果极其夸张。

**为什么这样赌：**

做教学的代价不是"多做几个关卡"。教学从底层传递的信号是"我不信任你"，这直接损害设计者契约。一个不信任玩家的游戏，无法建立玩家对游戏的信任。而三层信任（§2.7）是整个后续体验的基础。

### 1.3 设计六问

每一关设计前问自己两组问题：

**单关体验（做什么）：**

1. **核心矛盾是什么？**（不是"用了什么元素"，而是"玩家面临什么抉择"）
2. **节奏弧线是什么？**（开局→中盘→收尾各是什么体验？有没有转折点？）
3. **新手和老手分别会怎么玩？**（两种人都觉得好玩吗？）

**进度上下文（为什么在这里做）：**

4. **玩家在这一关应该发现什么？**（新的策略维度？或者纯存信任，不需要发现）
5. **发现它需要花多少信任？**（预计失败几次才能找到新策略？）
6. **当前信任余额够不够？**（前面的关卡存够了吗？如果不够，这关应该先存信任）

### 1.4 关于"新鲜感"

新鲜感不来自"没见过的元素"，而来自**"没预料到的局面"**。

- 错误做法：靠不断放出新元素维持新鲜感（内容消耗型，不可持续）
- 正确做法：用有限元素的组合制造无限的局面变化（组合爆炸型）

国际象棋所有棋子从第一局就全部存在，新鲜感来自棋局的组合，不是"第 50 局解锁新棋子"。

## 2. 心理学基础

### 2.1 多巴胺与不确定性

多巴胺释放量由**"预期与现实的差距"**决定（Wolfram Schultz），不是由奖励本身决定。

对关卡设计的启示：
- 完全在预期内的结果 → 无反应
- 意外的好结果 → 多巴胺飙升
- 静态关卡的问题：确定性单调递减 → 兴奋感单调递减

### 2.2 棋盘中的三种不确定性

| 类型 | 定义 | 设计手段 |
|------|------|---------|
| **信息不确定** | 棋盘上有我看不到的东西 | 障碍内容物（Box 里藏东西）、多层障碍遮挡 |
| **生成不确定** | 下一个掉下来的是什么 | Spawner 权重变化、颜色分布突变 |
| **后果不确定** | 我的操作会触发什么连锁 | cascade、炸弹引爆、死亡效果 |

好的关卡应该同时激活至少两种不确定性。

### 2.3 心流的挑战-技能平衡

静态关卡的问题：随着障碍减少，挑战低于技能 → 跌出心流进入无聊区。

解决方案：**通过 board 设计制造自然的阶段感**，在确定性即将坍缩时注入新的复杂性。

### 2.4 蔡格尼克效应

人对未完成的任务有强烈的心理挂念。利用方式：当玩家刚完成一个阶段（心理线程关闭），立刻展开新的挑战（重新激活）。

### 2.5 自我效能感

来自 Bandura（1977）社会认知理论。不是"你有没有能力"，而是**"你相不相信自己有能力"**。

**四个来源（按影响力从强到弱）：**

| 来源 | 机制 | 三消中的体现 |
|------|------|------------|
| **掌握经验** | 亲手做到了 → "我能行" | 每次过关且感觉是自己的决策导致的 |
| **替代经验** | 看到类似的人做到了 | replay、排行榜、"好友也在玩" |
| **言语说服** | 被告知"你可以" | UI 反馈："差一点！"、"好操作！" |
| **情绪状态** | 焦虑↓效能感，兴奋↑效能感 | 节奏设计避免连续焦虑 |

**关键：掌握经验中，过关的方式比过关本身更重要。** 靠运气过 → 不建立效能感。靠自己判断过 → 效能感猛增。三消随机性高（cascade ~50%），需要主动**放大技能信号**——好决策的结果应明显优于随机操作。

**自我效能感与失败的关系：**

```
效能感未建立时失败 → "我不行"        → 放弃
效能感已建立后失败 → "我还没找到方法"  → 继续尝试
```

"还没"这两个字就是一切。L001-L010 的核心任务就是帮玩家建立"我行"的信念。

**对关卡设计的要求：**
1. **早期胜利要感觉"赚来的"**：简单但不侮辱智商，玩家要有"我想到了"的感觉
2. **技能信号放大**：笨办法 ~40% 胜率 vs 聪明办法 ~90%，差距可感知
3. **失败必须可归因**：玩家能想到"下次我该先清底部" → 效能感不受损；想不到为什么失败 → 效能感崩塌

### 2.6 设计者契约

设计者与玩家之间隐性的、从不明说的承诺关系。

**设计者的五个承诺：**

| 承诺 | 含义 | 违反后果 |
|------|------|---------|
| **公平** | 每一关都有合理解法 | "这游戏骗钱" → 卸载 |
| **一致** | 规则不变，1HP Box 永远一击碎 | "我不知道该信什么" → 困惑 |
| **意图** | 难度是设计过的，不是 bug | "这关是不是出错了？" → 不信任 |
| **尊重** | 不浪费玩家时间 | "又要重复 10 次？" → 厌倦 |
| **诚实** | 视觉不骗人，看起来能打的就能打 | "我被耍了" → 愤怒 |

**契约不是通过说明书建立的，而是通过前 10 关的体验建立的。** 每一关就是一个数据点，玩家在无意识中统计设计者的可信度。10 关后形成判断："这个设计者靠谱/不靠谱。"

**契约建立后的威力**：遇到难关时，玩家第一反应不是"游戏有问题"，而是"我还没找到方法"——因为过去的体验告诉他设计者不会坑他。这就是塞尔达玩家被一个神庙卡 30 分钟还不放弃的原因。

**三消中的契约违反**：
- 一关需要极端运气才能过 → 违反公平
- 同一个障碍有时一击碎有时不碎 → 违反一致
- 毫无铺垫的难度跳崖 → 违反意图
- 必须重复 10 次靠运气过关 → 违反尊重
- 棋盘布局暗示从上打但正解是从下打 → 需要区分：事后回头看线索是否存在？存在 → 是"Aha!"发现；不存在 → 是欺骗

### 2.7 三层信任模型

从自我效能感（§2.5）和设计者契约（§2.6）推导出三层信任：

```
自我效能感 → 信任自己
设计者契约 → 信任游戏
两者叠加  → 信任探索
```

玩家在遇到挫败时是否继续尝试，取决于三层信任是否建立：

| 信任层 | 玩家内心 | 建立方式 |
|--------|---------|---------|
| **信任游戏** | "这关一定有解法，因为之前每一关都是公平的" | 前期关卡绝不坑人，每关解法清晰有逻辑 |
| **信任自己** | "我能搞定，因为我以前搞定过类似的" | 积累成功体验，明确的正反馈（奖励 + 胜利感） |
| **信任探索** | "试新方法有好处，因为上次试了就成功了" | 奖励"试试看"的行为，不同策略产生可感知的不同结果 |

缺任何一层，玩家都会在挫败时离开：
- 不信任游戏 → "这破游戏是不是 bug？" → 卸载
- 不信任自己 → "我太笨了" → 放弃
- 不信任探索 → "试什么都一样" → 无聊

### 2.8 信任银行与挫败容忍

```
每次公平的成功体验 = 存入 1 点信任
每次挫败            = 取出 2-3 点信任
信任归零            = 卸载
```

对关卡进度的含义：
- **L001-L010 是纯存款阶段**。每一关都要公平、流畅、有正反馈。绝不能出现"我不知道为什么失败了"的体验。
- **L011-L015 可以引入第一次"近失败"**。玩家可能失败 1 次，但调整策略后过关。消耗 2-3 点信任，成功后存回 + "Aha!" 奖励。
- **L020+ 可以有真正的挑战**。信任银行已经足够厚，能扛住 2-3 次失败。

**绝对红线：失败时的完成度比胜率更重要。**

玩家失败时只完成了目标的 30% → 觉得无望 → 离开。
玩家失败时完成了目标的 85% → "差一点！再来一次" → 留下。

调参时不仅看胜率，还要看**失败局的平均目标完成度**（应 > 75%）。

### 2.9 "Aha!" 时刻设计

三消中的"原来还可以这样！"是玩家**发现新的策略维度**的瞬间：

| 发现 | 玩家内心 |
|------|---------|
| 从底部消比从顶部消好得多 | "原来位置有讲究" |
| 先清障碍再收集，而不是同时做 | "原来有优先级" |
| 把炸弹留到合适时机再用 | "原来可以规划" |
| 4 连能出炸弹 | "原来我能制造这个" |

每个发现都是一次能力跃迁——玩家永久变强了。

**设计手法：堵住笨办法，奖励聪明办法。**

不是"只有一条路"，而是：
- 笨办法：能过，但很紧（~40-50% 胜率），经常差 1-2 步失败
- 聪明办法：一旦发现，轻松过关（90%+），甚至剩很多步

差距必须大到玩家能感知。如果笨办法也能轻松过 → 没有发现动力。如果笨办法完全不能过 → 不公平。

具体手法：

1. **空间诱导**：上方宽敞、下方封锁。笨办法在上方消（舒适但低效），聪明办法把消除引向下方（打破障碍后 cascade 爆发）
2. **目标优先级**：两个目标看似平等但有隐藏优先级。先做 A 再做 B 比同时做容易得多
3. **延迟满足**：开局送炸弹。立刻点 = 浪费，忍住等时机 = 一炸全清

## 3. 阶段感设计（伪波次系统）

### 3.1 为什么需要阶段感

单阶段关卡 = "看到全貌 → 逐步清除"，体验是单调递减的。

阶段感关卡 = "建立预期 → 打破预期 → 重建掌控"，对应三幕结构的叙事本能。

| 阶段 | 玩家体验 | 心理状态 |
|------|---------|---------|
| **建立**（阶段 1）| 观察棋盘，制定策略 | 掌控感 |
| **打破**（阶段 2 展开）| 棋盘结构变化，新局面 | 惊喜/紧张 |
| **重建**（适应并通关）| 用更高策略应对 | 成就感 |

### 3.2 体验模式库

在不增加新机制的前提下，用 board 设计制造阶段感。详见 `level-design/patterns/`：

| 模式 | 核心体验 | 详情 |
|------|---------|------|
| [决堤](patterns/dam-break.md) | 空间释放 + cascade 狂欢 | 障碍行破裂 → tile 涌入空白区 |
| [引爆](patterns/chain-detonation.md) | agency 放大感 | 小操作触发大爆炸 |
| [层层揭开](patterns/peeling.md) | 渐进推进感 | 从一端逐层突破覆盖层 |
| [内外翻转](patterns/inside-out.md) | 空间叙事感 | 从外围打开封闭结构 |
| [自教学](patterns/self-teaching.md) | 体验即教学 | 通过关卡结构引导学习 |
| [Boss 关](patterns/boss-level.md) | 综合检验 + 仪式感 | 多元素组合的节奏波峰 |
| [双目标](patterns/dual-objective.md) | 注意力分配 | 同向/中立/冲突三种组合 |
| [间接操作](patterns/indirect-operation.md) | 远程影响感 | 在 A 处操作 → B 处产生效果 |
| [颜色协同](patterns/color-synergy.md) | 策略收敛感 | 同色元素形成跨机制协同链 |
| [产出链](patterns/production-chain.md) | 破坏→创造感 | 死亡效果/生成器产出新目标 |
| [Cover 梯度](patterns/cover-gradient.md) | 渐进理解感 | Frost→Chain→Cage→Honey 难度阶梯 |
| [颜色张力](patterns/color-tension.md) | 策略切换感 | 颜色聚焦(ColorBox) vs 颜色多样性(PotionBottle) |

这些模式可以自由组合——比如决堤 + 引爆、层层揭开 + Boss、间接操作 + 颜色协同、Cover 梯度 + 层层揭开。

### 3.3 原语实现状态

| 原语 | 描述 | 状态 |
|------|------|------|
| **障碍内容物** | Cupboard 释放 Plate、Mailbox 释放 Envelope | ✅ 已实现 |
| **Spawner 激活/停用** | SpawnerPhaseConfig + obstacleCleared 触发器实现空间展开 | ✅ 已实现 |
| **Spawner 权重软切换** | 支持 per-Spawner 权重自定义（WeightedDefaultCondition），但尚无 phase 级权重切换 | ⚠️ 部分实现 |
| **新障碍品种** | 有固定死亡效果的新障碍（如 TreasureBox→释放炸弹、PandoraBox→喷 Honey） | ❌ 待建 |

原则：同种障碍行为恒定，差异通过"品种"体现，不做同一障碍可配置不同行为。

### 3.4 元素组合设计原理

通过系统性的机制交叉分析和测试关卡验证，发现以下元素组合原理：

#### 颜色是最强的策略轴

ColorBox、Curtain、ColorBomb 三者通过"颜色"这个维度产生深度组合。一旦玩家理解"颜色管理"，所有颜色相关机制的体验都会跃迁。

| 组合 | 协同机制 | 发现深度 |
|------|---------|---------|
| Curtain + ColorBomb | ColorBomb 是唯一能打 Curtain 的终极武器 | ★★★★★ |
| ColorBox + 颜色流管理 | 清非目标色 → 目标色自然流入 ColorBox 邻接 | ★★★ |
| 同色 Curtain + ColorBox | 一次颜色操作同时推进两种不同机制的障碍 | ★★★★ |
| ColorBomb + 同色 Curtain + ColorBox | 一次操作三重收益（颜色三角） | ★★★★★ |

#### 间接操作 > 直接操作

玩家的默认心智模型："操作影响范围 = 操作位置附近"。间接操作模式打破这个假设：

- **UFO 寻的**：在主区域造 UFO → 自动飞向远处 Safe（评分 90，全游戏最高优先级）
- **颜色流管理**：清除上方非目标色 → 目标色自然掉落到底部 ColorBox 旁
- **MagicHat 充能**：在 MagicHat 旁正常消除 → "免费"产出 Diamond

间接操作是三消中最稀缺的"高天花板"技能维度。

#### 死亡效果是天然的阶段感源

Bush/Flowerpot 的死亡效果让"破坏"行为产生"创造"结果，形成自然的二幕结构：

```
破坏行为 → 创造结果 → 新目标出现
Kill Bush → Grass 生长 → 收集 Grass
Kill Flowerpot → 3×3 Leaves 蔓延 → 收集 Leaves
```

与 Dam Break 结合时产生三层后果叠加：空间释放 + 产物生成 + 新目标。

#### 分析管线技能差距 = 设计价值信号

分析管线（随机/半随机 AI）越难通过的机制组合，说明对人类技能的回报越高：

| 机制 | 分析 AI 胜率 | 真实玩家预估 | 技能差距 |
|------|-------------|------------|---------|
| Safe 角落（需造 UFO） | ~14% | ~40-50% | 极大 |
| ColorBox 底部（需颜色流管理） | ~12% | ~35-50% | 极大 |
| Curtain（需理解触发规则） | ~68% | ~85%+ | 中等 |
| MagicHat（需邻接消除积累） | ~50% | ~75% | 中等 |

分析 AI 的局限性恰好度量了"策略回报空间"——这是"低地板高天花板"的核心。

#### Cover 难度梯度

代码分析揭示 4 种 Cover 形成清晰的难度阶梯，这决定了 Cover 系统的引入顺序：

| Cover | 允许匹配 | 邻接伤害 | 核心难度 | 推荐引入 |
|-------|---------|---------|---------|---------|
| **Frost** | ✅ | ✅ | 最低 — 多米诺式瓦解（18 Frost 平均 8 步清完） | Cover 首次出场 |
| **Chain** | ✅ | ❌ | 中等 — 必须消除下方 tile 才能破 | Frost 之后 |
| **Cage** | ❌ | ❌ | 高 — 只有炸弹直接命中 | Chain 之后 |
| **Honey** | ❌ | ✅ (仅 Match/ColorBomb) | 最高 — 炸弹无效，只有匹配有效 | 最后引入 |

关键发现：**Honey 完全免疫炸弹邻接伤害**。`ElimSource.Bomb` 不触发 Honey 邻接反应，只有 `Match`/`ColorBomb` 触发。设计 Honey 关卡时必须确保附近有可匹配空间，不能仅依赖炸弹。

Frost 场适合做"Cover 概念"首次出场（Frost Cascade 效果），也适合多幕关卡的 Act 1（信心建设器）。

#### 颜色聚焦 vs 颜色多样性

颜色条件性元素形成两个对立策略轴：

| 策略 | 元素 | 颜色需求 | 操作模式 |
|------|------|---------|---------|
| **颜色聚焦** | ColorBox, Curtain | 反复匹配一种颜色 | 集中、深度 |
| **颜色多样性** | PotionBottle | 依次匹配所有 4 种颜色 | 分散、广度 |

两者同时出场时产生**颜色张力**：左侧 ColorBox(红) + 右侧 PotionBottle → "左边要红色，右边要所有颜色"。
分析验证：15.6% Hard，Expert 32% vs Casual 15%，技能差距极大。

#### PotionBottle 的"悬崖"目标完成度

PotionBottle 有 4 个子瓶，目标追踪只在**全部破碎**时计 1。这意味着：
- 破了 3/4 子瓶 = 目标完成度 0%（因为障碍未被"清除"）
- 失败时平均完成度只有 23.5%（远低于 §2.8 的 75% 红线）

**设计规则**：PotionBottle **绝不能作为唯一目标**。必须搭配平滑进度的伴生目标（tile 收集、Ground 清除等），确保失败时整体完成度 > 75%。

## 4. 认知负荷管理

### 4.1 元素认知成本分级

元素分布在三套枚举中：GroundType（地面层）、CoverType（覆盖层）、ObstacleType（障碍层）。

| 认知成本 | 元素 | 层 | 原因 |
|---------|------|---|------|
| 低 | Ice | Ground | 视觉自解释，踩碎即可 |
| 低 | Box、Stone | Obstacle | 破坏逻辑直观（打就行） |
| 低 | Grass、Leaves | Ground | 死亡效果产物，自动出现 |
| 低 | 预置炸弹 | Tile | 视觉自解释 |
| 中 | Frost | Cover | 最宽容 Cover：允许匹配 + 邻接伤害 → 多米诺瓦解 |
| 中 | Chain | Cover | 中等 Cover：允许匹配但无邻接伤害 → 需消除下方 tile |
| 中 | Cage | Cover | 严格 Cover：阻止匹配 + 无邻接伤害 → 只能炸弹直接命中 |
| 中-高 | Honey | Cover | 最难 Cover：阻止匹配 + 只有 Match/ColorBomb 邻接有效（炸弹无效！） |
| 中 | Bubble | Cover | 唯一动态 Cover：允许匹配 + 跟随 tile 移动 |
| 中 | Bush、Safe、Owl | Obstacle | 需要理解免疫规则（Safe/Owl 免疫 Match） |
| 中 | Cupboard、Mailbox | Obstacle | 需要理解释放/生成机制 |
| 高 | MagicHat | Obstacle | 累计触发 + 生成特殊 tile |
| 高 | PotionBottle | Obstacle | 子瓶 bitmask + 颜色匹配 |
| 高 | ColorBox、Curtain | Obstacle | 需要理解颜色条件性交互规则 |

### 4.2 排列约束

- **单关新概念 <= 1**：每关最多出现一个玩家之前没见过的元素
- **单关元素总量 <= 4**：新旧加在一起不超过 4 种（King + Playrix 的行业共识，§9.2）
- **前 5 关**：只用低认知成本元素
- **6-20 关**：可引入中认知成本元素
- **20 关之后**：可引入高认知成本元素 + 多元素组合
- **任何位置**：已出现过的元素可自由组合

这比"每 15 关解锁一个"灵活，但仍然保证玩家不被认知负荷淹没。

### 4.3 自教学关卡设计

新机制首次出场时，通过关卡结构引导玩家，不通过弹窗：

- **数量最少**：首次只放 1-2 个新元素实例
- **位置显眼**：放在棋盘中心或必经路径
- **目标宽松**：步数充裕，允许试错
- **周围简单**：新元素附近不放其他复杂元素
- **结果即时**：操作新元素后立刻看到明显效果

### 4.4 机制教学分级

不是所有机制都需要主动教。分两类：

| 类别 | 定义 | 教学方式 | 示例 |
|------|------|---------|------|
| **低地板机制** | 不会就无法正常游玩 | 通过关卡结构强制体验（§4.3） | 交换消除、点击炸弹触发 |
| **高天花板技巧** | 不会也能过关，会了体验飞跃 | 不教，制造发现概率 | 4 连生成炸弹、T/L 形、炸弹+炸弹交换 |

**高天花板技巧的发现设计**：
- 确保自然游玩中该技巧**频繁出现**（如：4 色棋盘 + cascade = 4 连概率高）
- 触发效果**极其夸张**，让"不小心触发"的玩家立刻注意到
- 不惩罚不知道的人：所有关卡都能不用高级技巧通过

**判断标准**：不会这个技巧能不能通关？能 → 高天花板，不需要教。不能 → 低地板，必须通过关卡结构教。

## 5. 前期关卡策略

### 5.1 前 20 关的任务

前 20 关不是教学，是**试镜**。玩家在问："这个游戏和我玩过的有什么不同？"

2026 年的三消用户画像：
- 大多数已玩过至少一款三消，基础机制不需要教
- 前 20 关的平淡教学 = "这游戏不把我当回事"
- 你有 10-15 关的时间证明"这个游戏值得玩下去"

### 5.2 同一关，不同体验层

不分类玩家，让关卡自适应：

| 维度 | 设计要求 |
|------|---------|
| **低地板** | 即使随便玩也能通关（步数宽裕、预置炸弹兜底） |
| **高天花板** | 精准操作显著减少步数（多出的步数 → 高星级） |
| **自然引导** | 关卡结构让新手"不得不"以接近正确的方式玩 |

星级系统是天然的自适应机制：新手 1 星通关，老手 3 星通关，不需要给不同关卡。

### 5.3 不做前期玩家分类

原因：三消结果方差太大（cascade 随机 ~50%，Spawner ~20%，玩家决策 ~30%），1-3 关的样本量下信号不足。误分类代价不对称——把老手判成新手导致流失的代价远高于反之。

如果需要微调，最安全的方式：只调步数余量（±2 步），基于 5 关累积数据，不改变关卡内容。

## 6. 难度调节

### 6.1 信任驱动 vs 机械式曲线

传统做法是预设一条胜率曲线（95%→90%→70%→95%→...），让玩家在松紧交替中前进。问题是：这条曲线不关心玩家在每个节点学到了什么，难度起伏本身没有意义。

信任驱动的做法：

| | 机械式曲线 | 信任驱动曲线 |
|--|----------|------------|
| 难度的目的 | 制造"松紧节奏感" | 制造"发现时刻" |
| 简单关的目的 | 让玩家喘口气 | 存信任，为下次发现做准备 |
| 困难关的度量 | 胜率低 = 难 | 需要新策略 = 难 |
| 失败的含义 | 运气不好/水平不够 | 还没找到方法（但方法存在） |
| 成功的收获 | 过关了 | 我永久变强了 |

**设计难度时的正确问法**：不是"这关的胜率应该是多少"，而是：
1. 玩家在这一关应该发现什么？（对应 §1.2 问题 4-6）
2. 发现它需要花多少信任？
3. 当前信任余额够不够？
4. 发现之后能赚回多少？（策略越通用，回报越高）

### 6.2 调节手段优先级

| 优先级 | 手段 | 灵敏度 | 风险 |
|--------|------|--------|------|
| 1（首选）| 步数 ±1~2 | ±3-5% 胜率 | 极低 |
| 2 | 颜色数 ±1 | 显著 | 低 |
| 3 | 目标数量 | 中等 | 中 |
| 4 | 障碍数量/HP | 中等 | 中 |
| 5（最后）| 棋盘形状 | 最大 | 高 |

详见 `docs/03-design/level-knowledge/core/difficulty-levers.md`

### 6.3 分析管线注意事项

- 分析服务用纯随机 SpawnModel，TargetDifficulty 不影响分析结果
- 分析胜率是"纯随机玩家"的下界，粗略估计：分析 70% ≈ 实际 85%+
- `grid: null` 会导致非 8x8 关卡分析崩溃，必须提供显式 Grid 数组
- Cage 不能作为胜利目标条件（random 玩家 0% 胜率）
- Ice 目标数 10→11 有 ~15% 胜率跳变（容错从 5 块降到 4 块是质变）

## 7. 协作模式

### 7.1 分工

| 阶段 | 方式 |
|------|------|
| **前期（L1-30）** | 用户定设计意图，AI 实现和验证，逐关手工打磨 |
| **中后期** | AI 基于积累的设计原则自主生产，用户质检纠偏 |
| **持续** | AI 在批量生产中识别有价值的新组合模式，主动标记和复用 |

### 7.1.1 视觉审美流程

关卡的视觉设计感（造型、布局、元素密度）通过**渲染→视觉评估→迭代**的闭环保证：

```
设计 JSON → python scripts/render_level.py 渲染图片 → 看图评估 → 调整 → 重新渲染
```

纯逻辑推理（对称性、间距）只能解决 ~70% 的审美问题。剩余 30% 是格式塔感知（整体"空不空"、图案像不像东西、视觉重量分布），必须看图才能判断。

**审美模型路线：**

| 阶段 | 数据量 | 能力 | 标注方式 |
|------|--------|------|---------|
| 前期（当前） | 0-300 关 | AI 渲染+自评初筛，人工终审 | 人工二分类（过/不过） |
| 中期 | 300-500 关 | 训练首版审美模型，自动过滤明显差的 | 配对比较（A vs B 哪个好看） |
| 后期 | 800+ 关 | 多维评分模型（造型/密度/层次），替代人工初筛 | 多维评分 1-5 |

前期人工审核的数据**必须保留**——每一次筛选都是后续模型的训练燃料。

**额外数据源**：竞品（Royal Match / Candy Crush）的关卡截图可作为"正样本"补充，无需标注。

### 7.2 单关制作流程

```
1. 明确设计意图（核心矛盾、节奏弧线、体验目标）
2. 造型+机制同步设计 LevelConfig JSON
   - 造型和机制同步，不先画形状再塞元素
   - 造型本身要服务于重力流和匹配空间
3. 视觉审查（渲染→看图→迭代，两轮）
   python scripts/render_level.py config/levels/XXX.json /tmp/XXX.png

   第一轮 — 审美：
   - 元素密度够不够？图案清晰吗？构图平衡吗？
   
   第二轮 — 叙事（必须看图，纯逻辑不够）：
   - 焦点：一眼能找到目标元素在哪吗？
   - 方向：能感知"从哪开始"吗？
   - 层次：前景/中景/背景分得开吗？
   
   两轮都满意才进入下一步。不满意就调整 JSON 重新渲染
4. 分析管线验证（胜率、死锁率）
5. 数值调参迭代（优先调步数）
6. 沉淀设计记录到 level-design/levels/LXXX.md
```

### 7.3 每关设计检查清单

做完一关后，过一遍这三张清单：

**视觉审美检查（渲染图 — 第一轮）：**
- [ ] 元素密度足够？（元素占可用格子的 30-50%，不能太空）
- [ ] 图案可识别？（元素布局形成明确的视觉图案，不是随机散点）
- [ ] 构图平衡？（视觉重心不偏向某一侧）
- [ ] 层次丰富？（至少 2 层叠加：Ground + Obstacle 或 Cover + Obstacle）
- [ ] 轮廓有造型？（非矩形，有削角/镂空/异形）
- [ ] 与近邻关卡造型有差异？（连续 3 关不能都是同一种轮廓）

**视觉叙事检查（渲染图 — 第二轮，必须看图判断）：**
- [ ] 焦点明确？（目标元素形成视觉团块，不是散点。玩家一眼能找到"要打什么"）
- [ ] 方向引导？（疏密梯度暗示从哪开始。如：上空下密 = 从上往下打）
- [ ] 策略暗示？（布局是否暗示了优先级？如：中间障碍门 = "先打通门"）
- [ ] 视觉层次？（前景焦点 + 中景结构 + 背景区域，三层可分辨）

注意：视觉叙事纯逻辑推理只能做 ~70%，剩余 30% 是格式塔感知，**必须渲染看图**才能判断。

**自我效能感检查（§2.5）：**
- [ ] 玩家过关时，能感知到是自己的决策导致的成功吗？（不是纯运气）
- [ ] 玩家失败时，能想到下次可以怎么做不同吗？（失败可归因）
- [ ] 这关的挑战是否建立在之前某关教过的策略之上？（渐进性）
- [ ] 难度是否在"努力一下就能够到"的范围内？（不打击信念）

**设计者契约检查（§2.6）：**
- [ ] 这关有合理的可发现策略吗？（公平）
- [ ] 所有元素行为与之前一致吗？（一致）
- [ ] 难度与玩家当前信任余额匹配吗？（尊重）
- [ ] 视觉线索诚实吗？如果正解是"先清底部"，底部是否有吸引注意力的视觉暗示？（诚实）

## 8. 做关必知（踩坑经验）

| 经验 | 详情 |
|------|------|
| grid:null 崩溃 | 非 8x8 关卡必须提供显式 Grid 数组 |
| Cage 目标 0% | Cage 只能作为观察元素，不能作为胜利条件 |
| Ice 跳变 | Ice 目标 10→11 有 ~15% 胜率断崖 |
| 步数精度 | ±1 步 ≈ ±3-5% 胜率，是最精准的调参旋钮 |
| Cage 中部死锁 | 4 Cage 交错放中间 → 14.8% 死锁；底部放 → 正常 |
| Spawner 设计 | 只帮不害，seed 粗调 + SpawnModel 安全网（80/20） |
| Safe/Owl/Stone 分析 0% | 分析管线曾有 bug：BombResolution 未注入 ExplosionSystem，炸弹爆炸无法命中 bomb-only 障碍。已修复（RandomAnalysisService + SharedSimulationContext） |
| 坝后空行死锁 | KeepEmpty 空行越多死锁率越高：4 行 = 28%，2 行 = 18%。坝式结构建议 ≤ 2 行空白 |
| ColorBox 目标难度 | ColorBox 对分析 AI 极难（~12% 胜率），因为需要颜色意识。真实玩家 35-50%，差距说明技能回报高 |
| PotionBottle 悬崖 | PotionBottle 4 子瓶全破才计 1 目标 → 失败完成度仅 23.5%（远低于 75% 红线）。永远搭配伴生目标 |
| Honey 炸弹无效 | `ElimSource.Bomb` 不触发 Honey 邻接伤害。放 Honey 时必须确保附近有匹配空间，不能仅靠炸弹 |
| Bubble 覆写 Cage | 动态 Bubble 移动到 Cage cell 时 SetCover 会覆写 Cage → Cage 静默消失。**潜在 bug**，同关勿混用 Bubble + Cage 在可接触区域 |
| 移动障碍 + Sink | 非 collectible 移动障碍到达 Sink 后永久占位阻塞列。Sink 行关卡避免使用 RoyalEgg/Vase 等 |
| Frost 场太快 | 18 Frost 平均 8 步清完（91.8%）。Frost 场适合做信心建设，不适合做挑战 |

## 9. 行业经验方法（竞品研究提炼）

从 Royal Match、Candy Crush Saga、Gardenscapes/Homescapes、Toon Blast、Toy Blast、Project Makeover 等顶级三消产品的设计实践中提炼，已过滤掉与本项目哲学冲突的手段（如隐性 spawn 操控、强制惜败）。

详细竞品数据见 `level-design/competitor-early-levels-analysis.md`。

### 9.1 颜色数是最强的隐性难度旋钮

**行业共识**：颜色数的影响远超大多数设计者的直觉。

| 颜色数 | 效果 | 适用场景 |
|--------|------|---------|
| 3 | 极简单。cascade 概率极高，棋盘几乎自己在玩 | 教学、"wow" 级、纯放松 |
| 4 | 标准偏易。自然 4 连频繁，power-up 大量产生 | 前 20 关默认值（Royal Match 前 230 关用 4 色） |
| 5 | 标准难度。匹配机会适中 | 中期关卡主力 |
| 6 | 困难。自然匹配稀少，board 感觉"紧" | 后期、技巧检验关 |

**关键数据**：Candy Crush Level 65（史上最赚钱关卡）从 5 色改为 4 色后，每次匹配的平均清除从 3.0 块跳到 5.25 块——提升 75%，但玩家几乎无感。

**对本项目的意义**：
- 前期默认 4 色，这是 Royal Match 成功的核心因素之一
- 4 色时 4 连消极其频繁 → 玩家自然大量生成炸弹 → 不需要教就能发现炸弹机制
- 符合我们的"体验即教学"和"高天花板技巧不教"原则
- 5→4 色的 ±20-30% spawn 权重调整玩家完全无感，是最安全的微调手段

### 9.2 单关最多 4 种元素

**行业共识**（King GDC 2016、Playrix DevGAMM 2019 均明确提出）：

> "No more than 4 different elements per level to avoid confusing the player."

这不是我们的"单关新概念 ≤ 1"的替代，而是补充约束：
- §4.2 控制**新概念引入节奏**（每关最多 1 个新元素）
- 本条控制**单关元素总量**（新旧加在一起不超过 4 种）
- 复杂度来自元素**组合**，不来自元素**数量**

### 9.3 新元素引入的标准流程

综合 Royal Match、Candy Crush、Toon Blast 的共同做法：

**引入关（第 1 关）**：
1. 只放新元素，不与旧元素混合
2. 数量少（1-3 个实例）
3. 步数额外宽裕（比同期关卡多 30-50%）
4. 目标简单，允许多次试错

**巩固关（第 2-3 关）**：
1. 新元素开始与 1 种已学元素组合
2. 步数恢复正常水平
3. 新元素数量增加到 4-6 个

**融合关（第 4+ 关）**：
1. 新元素自由与多种已学元素组合
2. 可以出现在棋盘的困难位置（边角、瓶颈区）

**引入节奏参考**：
- Royal Match：前期 4-5 关一个新元素，L20 后 10 关一个
- Candy Crush：约 5-8 关一个新元素
- 本项目建议：参考 Royal Match 的克制节奏，前 50 关约 6 种障碍

### 9.4 难度周期设计

**行业共同模式**：所有成功产品都使用 5-15 关的难度波次循环。

```
信任关(简单) → 渐进 → 渐进 → 峰值(困难) → 缓冲(简单) → 信任关 → ...
```

具体参数（综合 Royal Match + Candy Crush）：

| 位置 | 难度 | 目的 |
|------|------|------|
| 周期第 1 关 | 刻意简单 | 存信任，建立"又能赢"的预期 |
| 第 2-3 关 | 逐步上升 | 引入本周期的核心挑战 |
| 第 4-5 关 | 高峰 | 需要发现新策略或精准操作 |
| 第 6-7 关 | 缓冲 | 奖励性关卡，让玩家用新学的技巧爽一把 |

**Royal Match 的 x9/x0 节奏**：
- 每 10 关末尾（x9）是该段最难关
- 每 10 关整数（x0）是 bonus 奖励关（无目标，纯收集金币）
- 这创造了"冲刺→奖励"的叙事节拍

**与我们的§2.8 信任银行的关系**：
- 简单关 = 存入信任（2-3 关连胜 ≈ 存 2-3 点）
- 难关 = 消耗信任（1 次失败 ≈ 取 2-3 点）
- 每个难度周期都是一个信任"收支平衡"

### 9.5 开局设计（Opening Move 技术）

**行业洞察**：关卡的前 1-3 步决定玩家对该关的第一印象。

**设计手法**：

1. **可见的好开局**：初始 board 上至少有一个明显的 4 连或 L 形机会，让玩家第一步就能创造 power-up
2. **预置炸弹引爆**：L1-5 放一个预置炸弹，玩家第一步交换或点击就看到大爆炸（我们的 L002 "Boom & Collect" 已经这么做了）
3. **底部集中同色**：底部区域放置较多同色 tile，第一步匹配就触发 cascade
4. **空间关系暗示**：开局 board 的形状就暗示了正确的策略方向（如窄底暗示"先从下面打"）

**注意**：开局好不等于关卡简单。好的开局是"hook"——第一步很爽，但后面需要策略。

### 9.6 Cascade 工程学

**行业手法（来自 board 设计，不涉及 spawn 操控）**：

**漏斗形 board**：上宽下窄，多 Spawner 列灌入少量活跃列 → cascade 概率在瓶颈区大增。

**Cascade 腔室**：被障碍封住的空白区域。打开障碍后，大量 tile 涌入空区 → 几乎必然产生连锁匹配。这就是我们的"决堤"模式的底层原理。

**交错障碍**：不同高度放置障碍，清除一个释放的 tile 正好落入下一个障碍的相邻区域 → 多米诺效应。

**垂直空间**：活跃区域上方保留足够高度（3+ 行 Spawner 或空格），给 cascade 提供"燃料"。

**关键原则**：cascade 的精彩程度来自 **board 拓扑**，不来自 spawn 偏向。这与我们的设计者契约（§2.6）完全一致——难度来自诚实的关卡设计。

### 9.7 Board 拓扑技巧

**空间类型**（行业通用分类）：

| 空间类型 | 效果 | 设计意图 |
|---------|------|---------|
| **瓶颈**（窄通道） | 限制 tile 流动，匹配机会少 | 制造局部紧张感 |
| **腔室**（封闭区域） | 独立空间，需要单独处理 | 多线程决策 |
| **漏斗**（上宽下窄） | 集中 tile 流向，cascade 放大 | 奖励底部操作 |
| **分割 board** | 两个独立区域共享步数 | 资源分配决策 |
| **传送门** | 连接非相邻区域 | 非线性重力路径 |
| **对称** | 可预测，视觉美观 | 降低认知负荷 |
| **非对称（对角线平衡）** | 内部重量差制造方向感 | 策略引导（操作区 vs 目标区）|
| **缺口入口** | 大面积障碍旁留小缺口 | 缺口 = 唯一操作起点 + 新元素展示位 |

**不对称设计原则**（Royal Match 验证）：

外框保持方正（稳定感），不对称靠**内部元素分布的重量差**实现，而非外轮廓异形。
不对称本质上仍然是对称的 — 只是对称轴不同：

| 不对称类型 | 对称轴 | 示例 |
|-----------|--------|------|
| 左右重量差 | 上下轴对称 | RM L17: 左 Box 团块 + 右缺口 |
| 对角重量差 | 对角线轴 | RM L2: 左下 Box + 右上空 |
| 上下重量差 | 左右轴对称 | 上空下密（常见方向引导） |

**缺口即入口**（Royal Match L17 验证）：

大面积障碍团块旁留一个小缺口。三重作用：
1. **操作入口**：障碍区无法匹配 → 缺口是唯一操作起点 → 玩家视线自然聚焦
2. **新元素展示**：缺口旁放新引入的元素 → 玩家操作时必然看到 → 体验即教学
3. **策略引导**：从缺口开始 → 逐步侵蚀障碍团块 → 方向感极其明确

**Playrix 的设计规则**：
- board 上不能有"废区域"——每个格子都要服务于关卡目标
- 至少保留 5 个空格子，确保购买的 booster 有地方放置
- board 形状本身就是"关卡的脸"，有辨识度的形状让关卡更记忆

### 9.8 关卡情感分类

**Room 8 Studio 的六类关卡**（补充我们的§3.2 体验模式库）：

| 类型 | 情感目标 | 元素数 | 对应我们的模式 |
|------|---------|--------|-------------|
| **Tutorial** | 安全学习 | 1-2 | 自教学模式 |
| **Wow** | 爽感爆发 | 2-3 | 决堤、引爆 |
| **Fuu** | 挫败（差 1-2 步）| 3-4 | — |
| **Procrastinating** | 放松 | 2-3 | 简单的双目标 |
| **Skill** | 策略检验 | 3-4 | Boss 关 |
| **Visualization** | 视觉愉悦 | 2-3 | — |

**注意**："Fuu" 类（故意设计差一点过不去）在商业游戏中用于驱动付费。对我们的项目：
- 不主动设计"故意差 1 步"的关卡（违反设计者契约 §2.6）
- 但自然出现的 near-miss 是好的（§2.8 信任银行的"差一点 → 再来一次"效应）
- 区别在于：near-miss 应该是**关卡难度的自然结果**，不是**spawn 操控的人工结果**

### 9.9 胜利时刻放大

**Sugar Crush 原则**（Candy Crush 发明）：

玩家通关后，剩余步数转化为 power-up，在 board 上连锁爆炸 → 视觉盛宴。

**为什么有效**：
- 剩余步数越多 → 爆炸越壮观 → "多余的步数有价值"的感觉
- 高手玩家（剩余步数多）获得更大的视觉奖励 → 技能信号放大（§2.5）
- 创造了关卡结束时的情绪高潮

**对本项目的启示**：我们已有星级系统（剩余步数 → 星级），但缺少通关时的**视觉庆祝**。建议：
- 通关后剩余步数自动触发 board 上的 cascade/爆炸
- 越多剩余步数 → 越壮观的结尾动画
- 这不影响核心玩法，只是纯表现层加分
