# 关卡设计框架

<!-- SOURCE_OF_TRUTH: level-design-framework -->

本文档是关卡设计的核心框架，所有关卡制作（手工或 AI 生产）必须遵循。

技术实现细节见 `docs/03-design/`，本文档聚焦**设计哲学和方法论**。

---

## 0. 第一原则

> **让玩家觉得是自己赢的。**

不是系统帮他赢的，不是运气让他赢的，不是付费买的胜利——是"我想到了，我做到了，我赢了"。

本文档所有设计原则均由此推导：
- 操作有意义 → 低地板高天花板、只帮不害、强控红线
- 发现是自己的 → 体验即教学、认知负荷管理、不确定性设计
- 失败是自己的 → 设计者契约、信任银行
- "赢"要有重量 → 阶段感、前期高密度、预期违背

当任何设计决策产生矛盾时，回到这一条判断。

## 1. 设计哲学

### 1.1 核心原则

1. **从心理学原理推导机制，不从竞品功能清单反推**
2. **体验即教学**：不用弹窗引导，通过关卡结构让玩家自然学会机制
3. **低地板高天花板**：新手能过、老手有追求，同一关产生不同层次的体验
4. **前期体验密度不低于中后期**：前 20 关是试镜，不是教学
5. **认知负荷通过单关元素数量控制**，不通过时间线限制元素可用性
6. **强控不能让玩家学到的东西失效**：动态难度调节可以抬高地板（帮助弱玩家），但不能压低天花板（削弱强玩家）。玩家通过游玩积累的知识和技能（如"操作底部 cascade 更长"、"主动制造炸弹组合"）必须始终有效。减小体验方差是合理的，但强制惜败或覆盖核心游戏规律是禁止的

### 1.2 核心赌注

以下是本项目最根本的设计决策。它决定了整个游戏的走向，尤其是前期体验。一旦改变，几乎所有关卡设计都要重来。

> **我们信任玩家。从第 1 关起就做真正的关卡，不做教学。**

具体含义：

1. **不做新手引导系统**。没有弹窗教学、没有强制箭头、没有"点击这里"。关卡结构本身就是教学。
2. **不做速通教学关**。L001 不是"只有 1 个有效 swap"的脚本化体验，而是一个有真正设计的关卡。
3. **高天花板技巧不教**。炸弹合成（4 连）、炸弹+炸弹交换等进阶技巧，通过自然游玩中频繁出现来让玩家自己发现。发现本身就是奖励。
4. **为体验设计，不为留存设计**。留存是好体验的自然结果。如果体验好但留存差，问题在体验，不在留存策略。

**我们在赌什么：**

- 赌 2026 年的三消用户大多玩过至少一款三消，不需要从零教起
- 赌玩家有能力自己发现规则，而这个发现过程本身比被教会更有价值（自我效能感 §2.5）
- 赌尊重玩家智商（设计者契约 §2.6）比防止极少数新手流失更重要

**风险：**

- 完全没玩过三消的纯新手可能在前几关懵几秒。缓解方案：空闲提示系统（N 秒无操作后高亮一个可消组合），这是 UI 层的轻提示，不是关卡层的强制引导。
- 少数玩家可能很晚才发现炸弹合成。缓解方案：确保自然游玩中 4 连频繁发生（4 色 + cascade），效果极其夸张。

**为什么这样赌：**

做教学的代价不是"多做几个关卡"。教学从底层传递的信号是"我不信任你"，这直接损害设计者契约。一个不信任玩家的游戏，无法建立玩家对游戏的信任。而三层信任（§2.7）是整个后续体验的基础。

### 1.3 设计六问

每一关设计前问自己两组问题：

**单关体验（做什么）：**

1. **核心矛盾是什么？**（不是"用了什么元素"，而是"玩家面临什么抉择"）
2. **节奏弧线是什么？**（开局→中盘→收尾各是什么体验？有没有转折点？）
3. **新手和老手分别会怎么玩？**（两种人都觉得好玩吗？）

**进度上下文（为什么在这里做）：**

4. **玩家在这一关应该发现什么？**（新的策略维度？或者纯存信任，不需要发现）
5. **发现它需要花多少信任？**（预计失败几次才能找到新策略？）
6. **当前信任余额够不够？**（前面的关卡存够了吗？如果不够，这关应该先存信任）

### 1.4 关于"新鲜感"

新鲜感不来自"没见过的元素"，而来自**"没预料到的局面"**。

- 错误做法：靠不断放出新元素维持新鲜感（内容消耗型，不可持续）
- 正确做法：用有限元素的组合制造无限的局面变化（组合爆炸型）

国际象棋所有棋子从第一局就全部存在，新鲜感来自棋局的组合，不是"第 50 局解锁新棋子"。

## 2. 心理学基础

### 2.1 多巴胺与不确定性

多巴胺释放量由**"预期与现实的差距"**决定（Wolfram Schultz），不是由奖励本身决定。

对关卡设计的启示：
- 完全在预期内的结果 → 无反应
- 意外的好结果 → 多巴胺飙升
- 静态关卡的问题：确定性单调递减 → 兴奋感单调递减

### 2.2 棋盘中的三种不确定性

| 类型 | 定义 | 设计手段 |
|------|------|---------|
| **信息不确定** | 棋盘上有我看不到的东西 | 障碍内容物（Box 里藏东西）、多层障碍遮挡 |
| **生成不确定** | 下一个掉下来的是什么 | Spawner 权重变化、颜色分布突变 |
| **后果不确定** | 我的操作会触发什么连锁 | cascade、炸弹引爆、死亡效果 |

好的关卡应该同时激活至少两种不确定性。

### 2.3 心流的挑战-技能平衡

静态关卡的问题：随着障碍减少，挑战低于技能 → 跌出心流进入无聊区。

解决方案：**通过 board 设计制造自然的阶段感**，在确定性即将坍缩时注入新的复杂性。

### 2.4 蔡格尼克效应

人对未完成的任务有强烈的心理挂念。利用方式：当玩家刚完成一个阶段（心理线程关闭），立刻展开新的挑战（重新激活）。

### 2.5 自我效能感

来自 Bandura（1977）社会认知理论。不是"你有没有能力"，而是**"你相不相信自己有能力"**。

**四个来源（按影响力从强到弱）：**

| 来源 | 机制 | 三消中的体现 |
|------|------|------------|
| **掌握经验** | 亲手做到了 → "我能行" | 每次过关且感觉是自己的决策导致的 |
| **替代经验** | 看到类似的人做到了 | replay、排行榜、"好友也在玩" |
| **言语说服** | 被告知"你可以" | UI 反馈："差一点！"、"好操作！" |
| **情绪状态** | 焦虑↓效能感，兴奋↑效能感 | 节奏设计避免连续焦虑 |

**关键：掌握经验中，过关的方式比过关本身更重要。** 靠运气过 → 不建立效能感。靠自己判断过 → 效能感猛增。三消随机性高（cascade ~50%），需要主动**放大技能信号**——好决策的结果应明显优于随机操作。

**自我效能感与失败的关系：**

```
效能感未建立时失败 → "我不行"        → 放弃
效能感已建立后失败 → "我还没找到方法"  → 继续尝试
```

"还没"这两个字就是一切。L001-L010 的核心任务就是帮玩家建立"我行"的信念。

**对关卡设计的要求：**
1. **早期胜利要感觉"赚来的"**：简单但不侮辱智商，玩家要有"我想到了"的感觉
2. **技能信号放大**：笨办法 ~40% 胜率 vs 聪明办法 ~90%，差距可感知
3. **失败必须可归因**：玩家能想到"下次我该先清底部" → 效能感不受损；想不到为什么失败 → 效能感崩塌

### 2.6 设计者契约

设计者与玩家之间隐性的、从不明说的承诺关系。

**设计者的五个承诺：**

| 承诺 | 含义 | 违反后果 |
|------|------|---------|
| **公平** | 每一关都有合理解法 | "这游戏骗钱" → 卸载 |
| **一致** | 规则不变，1HP Box 永远一击碎 | "我不知道该信什么" → 困惑 |
| **意图** | 难度是设计过的，不是 bug | "这关是不是出错了？" → 不信任 |
| **尊重** | 不浪费玩家时间 | "又要重复 10 次？" → 厌倦 |
| **诚实** | 视觉不骗人，看起来能打的就能打 | "我被耍了" → 愤怒 |

**契约不是通过说明书建立的，而是通过前 10 关的体验建立的。** 每一关就是一个数据点，玩家在无意识中统计设计者的可信度。10 关后形成判断："这个设计者靠谱/不靠谱。"

**契约建立后的威力**：遇到难关时，玩家第一反应不是"游戏有问题"，而是"我还没找到方法"——因为过去的体验告诉他设计者不会坑他。这就是塞尔达玩家被一个神庙卡 30 分钟还不放弃的原因。

**三消中的契约违反**：
- 一关需要极端运气才能过 → 违反公平
- 同一个障碍有时一击碎有时不碎 → 违反一致
- 毫无铺垫的难度跳崖 → 违反意图
- 必须重复 10 次靠运气过关 → 违反尊重
- 棋盘布局暗示从上打但正解是从下打 → 需要区分：事后回头看线索是否存在？存在 → 是"Aha!"发现；不存在 → 是欺骗

### 2.7 三层信任模型

从自我效能感（§2.5）和设计者契约（§2.6）推导出三层信任：

```
自我效能感 → 信任自己
设计者契约 → 信任游戏
两者叠加  → 信任探索
```

玩家在遇到挫败时是否继续尝试，取决于三层信任是否建立：

| 信任层 | 玩家内心 | 建立方式 |
|--------|---------|---------|
| **信任游戏** | "这关一定有解法，因为之前每一关都是公平的" | 前期关卡绝不坑人，每关解法清晰有逻辑 |
| **信任自己** | "我能搞定，因为我以前搞定过类似的" | 积累成功体验，明确的正反馈（奖励 + 胜利感） |
| **信任探索** | "试新方法有好处，因为上次试了就成功了" | 奖励"试试看"的行为，不同策略产生可感知的不同结果 |

缺任何一层，玩家都会在挫败时离开：
- 不信任游戏 → "这破游戏是不是 bug？" → 卸载
- 不信任自己 → "我太笨了" → 放弃
- 不信任探索 → "试什么都一样" → 无聊

### 2.8 信任银行与挫败容忍

```
每次公平的成功体验 = 存入 1 点信任
每次挫败            = 取出 2-3 点信任
信任归零            = 卸载
```

对关卡进度的含义：
- **L001-L010 是纯存款阶段**。每一关都要公平、流畅、有正反馈。绝不能出现"我不知道为什么失败了"的体验。
- **L011-L015 可以引入第一次"近失败"**。玩家可能失败 1 次，但调整策略后过关。消耗 2-3 点信任，成功后存回 + "Aha!" 奖励。
- **L020+ 可以有真正的挑战**。信任银行已经足够厚，能扛住 2-3 次失败。

**绝对红线：失败时的完成度比胜率更重要。**

玩家失败时只完成了目标的 30% → 觉得无望 → 离开。
玩家失败时完成了目标的 85% → "差一点！再来一次" → 留下。

调参时不仅看胜率，还要看**失败局的平均目标完成度**（应 > 75%）。

### 2.9 "Aha!" 时刻设计

三消中的"原来还可以这样！"是玩家**发现新的策略维度**的瞬间：

| 发现 | 玩家内心 |
|------|---------|
| 从底部消比从顶部消好得多 | "原来位置有讲究" |
| 先清障碍再收集，而不是同时做 | "原来有优先级" |
| 把炸弹留到合适时机再用 | "原来可以规划" |
| 4 连能出炸弹 | "原来我能制造这个" |

每个发现都是一次能力跃迁——玩家永久变强了。

**设计手法：堵住笨办法，奖励聪明办法。**

不是"只有一条路"，而是：
- 笨办法：能过，但很紧（~40-50% 胜率），经常差 1-2 步失败
- 聪明办法：一旦发现，轻松过关（90%+），甚至剩很多步

差距必须大到玩家能感知。如果笨办法也能轻松过 → 没有发现动力。如果笨办法完全不能过 → 不公平。

具体手法：

1. **空间诱导**：上方宽敞、下方封锁。笨办法在上方消（舒适但低效），聪明办法把消除引向下方（打破障碍后 cascade 爆发）
2. **目标优先级**：两个目标看似平等但有隐藏优先级。先做 A 再做 B 比同时做容易得多
3. **延迟满足**：开局送炸弹。立刻点 = 浪费，忍住等时机 = 一炸全清

## 3. 阶段感设计（伪波次系统）

### 3.1 为什么需要阶段感

单阶段关卡 = "看到全貌 → 逐步清除"，体验是单调递减的。

阶段感关卡 = "建立预期 → 打破预期 → 重建掌控"，对应三幕结构的叙事本能。

| 阶段 | 玩家体验 | 心理状态 |
|------|---------|---------|
| **建立**（阶段 1）| 观察棋盘，制定策略 | 掌控感 |
| **打破**（阶段 2 展开）| 棋盘结构变化，新局面 | 惊喜/紧张 |
| **重建**（适应并通关）| 用更高策略应对 | 成就感 |

### 3.2 体验模式库

在不增加新机制的前提下，用 board 设计制造阶段感。详见 `level-design/patterns/`：

| 模式 | 核心体验 | 详情 |
|------|---------|------|
| [决堤](patterns/dam-break.md) | 空间释放 + cascade 狂欢 | 障碍行破裂 → tile 涌入空白区 |
| [引爆](patterns/chain-detonation.md) | agency 放大感 | 小操作触发大爆炸 |
| [层层揭开](patterns/peeling.md) | 渐进推进感 | 从一端逐层突破覆盖层 |
| [内外翻转](patterns/inside-out.md) | 空间叙事感 | 从外围打开封闭结构 |
| [自教学](patterns/self-teaching.md) | 体验即教学 | 通过关卡结构引导学习 |
| [Boss 关](patterns/boss-level.md) | 综合检验 + 仪式感 | 多元素组合的节奏波峰 |
| [双目标](patterns/dual-objective.md) | 注意力分配 | 同向/中立/冲突三种组合 |

这些模式可以自由组合——比如决堤 + 引爆、层层揭开 + Boss。

### 3.3 原语实现状态

| 原语 | 描述 | 状态 |
|------|------|------|
| **障碍内容物** | Cupboard 释放 Plate、Mailbox 释放 Envelope | ✅ 已实现 |
| **Spawner 激活/停用** | SpawnerPhaseConfig + obstacleCleared 触发器实现空间展开 | ✅ 已实现 |
| **Spawner 权重软切换** | 支持 per-Spawner 权重自定义（WeightedDefaultCondition），但尚无 phase 级权重切换 | ⚠️ 部分实现 |
| **新障碍品种** | 有固定死亡效果的新障碍（如 TreasureBox→释放炸弹、PandoraBox→喷 Honey） | ❌ 待建 |

原则：同种障碍行为恒定，差异通过"品种"体现，不做同一障碍可配置不同行为。

## 4. 认知负荷管理

### 4.1 元素认知成本分级

元素分布在三套枚举中：GroundType（地面层）、CoverType（覆盖层）、ObstacleType（障碍层）。

| 认知成本 | 元素 | 层 | 原因 |
|---------|------|---|------|
| 低 | Ice | Ground | 视觉自解释，踩碎即可 |
| 低 | Box、Stone | Obstacle | 破坏逻辑直观（打就行） |
| 低 | Grass、Leaves | Ground | 死亡效果产物，自动出现 |
| 低 | 预置炸弹 | Tile | 视觉自解释 |
| 中 | Cage、Chain、Frost | Cover | 需要理解"它限制了什么" |
| 中 | Honey、Bubble | Cover | 需要理解扩散/移动机制 |
| 中 | Bush、Safe、Owl | Obstacle | 需要理解免疫规则（Safe/Owl 免疫 Match） |
| 中 | Cupboard、Mailbox | Obstacle | 需要理解释放/生成机制 |
| 高 | MagicHat | Obstacle | 累计触发 + 生成特殊 tile |
| 高 | PotionBottle | Obstacle | 子瓶 bitmask + 颜色匹配 |
| 高 | ColorBox、Curtain | Obstacle | 需要理解颜色条件性交互规则 |

### 4.2 排列约束

- **单关新概念 <= 1**：每关最多出现一个玩家之前没见过的元素
- **前 5 关**：只用低认知成本元素
- **6-20 关**：可引入中认知成本元素
- **20 关之后**：可引入高认知成本元素 + 多元素组合
- **任何位置**：已出现过的元素可自由组合

这比"每 15 关解锁一个"灵活，但仍然保证玩家不被认知负荷淹没。

### 4.3 自教学关卡设计

新机制首次出场时，通过关卡结构引导玩家，不通过弹窗：

- **数量最少**：首次只放 1-2 个新元素实例
- **位置显眼**：放在棋盘中心或必经路径
- **目标宽松**：步数充裕，允许试错
- **周围简单**：新元素附近不放其他复杂元素
- **结果即时**：操作新元素后立刻看到明显效果

### 4.4 机制教学分级

不是所有机制都需要主动教。分两类：

| 类别 | 定义 | 教学方式 | 示例 |
|------|------|---------|------|
| **低地板机制** | 不会就无法正常游玩 | 通过关卡结构强制体验（§4.3） | 交换消除、点击炸弹触发 |
| **高天花板技巧** | 不会也能过关，会了体验飞跃 | 不教，制造发现概率 | 4 连生成炸弹、T/L 形、炸弹+炸弹交换 |

**高天花板技巧的发现设计**：
- 确保自然游玩中该技巧**频繁出现**（如：4 色棋盘 + cascade = 4 连概率高）
- 触发效果**极其夸张**，让"不小心触发"的玩家立刻注意到
- 不惩罚不知道的人：所有关卡都能不用高级技巧通过

**判断标准**：不会这个技巧能不能通关？能 → 高天花板，不需要教。不能 → 低地板，必须通过关卡结构教。

## 5. 前期关卡策略

### 5.1 前 20 关的任务

前 20 关不是教学，是**试镜**。玩家在问："这个游戏和我玩过的有什么不同？"

2026 年的三消用户画像：
- 大多数已玩过至少一款三消，基础机制不需要教
- 前 20 关的平淡教学 = "这游戏不把我当回事"
- 你有 10-15 关的时间证明"这个游戏值得玩下去"

### 5.2 同一关，不同体验层

不分类玩家，让关卡自适应：

| 维度 | 设计要求 |
|------|---------|
| **低地板** | 即使随便玩也能通关（步数宽裕、预置炸弹兜底） |
| **高天花板** | 精准操作显著减少步数（多出的步数 → 高星级） |
| **自然引导** | 关卡结构让新手"不得不"以接近正确的方式玩 |

星级系统是天然的自适应机制：新手 1 星通关，老手 3 星通关，不需要给不同关卡。

### 5.3 不做前期玩家分类

原因：三消结果方差太大（cascade 随机 ~50%，Spawner ~20%，玩家决策 ~30%），1-3 关的样本量下信号不足。误分类代价不对称——把老手判成新手导致流失的代价远高于反之。

如果需要微调，最安全的方式：只调步数余量（±2 步），基于 5 关累积数据，不改变关卡内容。

## 6. 难度调节

### 6.1 信任驱动 vs 机械式曲线

传统做法是预设一条胜率曲线（95%→90%→70%→95%→...），让玩家在松紧交替中前进。问题是：这条曲线不关心玩家在每个节点学到了什么，难度起伏本身没有意义。

信任驱动的做法：

| | 机械式曲线 | 信任驱动曲线 |
|--|----------|------------|
| 难度的目的 | 制造"松紧节奏感" | 制造"发现时刻" |
| 简单关的目的 | 让玩家喘口气 | 存信任，为下次发现做准备 |
| 困难关的度量 | 胜率低 = 难 | 需要新策略 = 难 |
| 失败的含义 | 运气不好/水平不够 | 还没找到方法（但方法存在） |
| 成功的收获 | 过关了 | 我永久变强了 |

**设计难度时的正确问法**：不是"这关的胜率应该是多少"，而是：
1. 玩家在这一关应该发现什么？（对应 §1.2 问题 4-6）
2. 发现它需要花多少信任？
3. 当前信任余额够不够？
4. 发现之后能赚回多少？（策略越通用，回报越高）

### 6.2 调节手段优先级

| 优先级 | 手段 | 灵敏度 | 风险 |
|--------|------|--------|------|
| 1（首选）| 步数 ±1~2 | ±3-5% 胜率 | 极低 |
| 2 | 颜色数 ±1 | 显著 | 低 |
| 3 | 目标数量 | 中等 | 中 |
| 4 | 障碍数量/HP | 中等 | 中 |
| 5（最后）| 棋盘形状 | 最大 | 高 |

详见 `docs/03-design/level-knowledge/core/difficulty-levers.md`

### 6.3 分析管线注意事项

- 分析服务用纯随机 SpawnModel，TargetDifficulty 不影响分析结果
- 分析胜率是"纯随机玩家"的下界，粗略估计：分析 70% ≈ 实际 85%+
- `grid: null` 会导致非 8x8 关卡分析崩溃，必须提供显式 Grid 数组
- Cage 不能作为胜利目标条件（random 玩家 0% 胜率）
- Ice 目标数 10→11 有 ~15% 胜率跳变（容错从 5 块降到 4 块是质变）

## 7. 协作模式

### 7.1 分工

| 阶段 | 方式 |
|------|------|
| **前期（L1-30）** | 用户定设计意图，AI 实现和验证，逐关手工打磨 |
| **中后期** | AI 基于积累的设计原则自主生产，用户质检纠偏 |
| **持续** | AI 在批量生产中识别有价值的新组合模式，主动标记和复用 |

### 7.2 单关制作流程

```
1. 明确设计意图（核心矛盾、节奏弧线、体验目标）
2. 制作 LevelConfig JSON
3. 分析管线验证（胜率、死锁率）
4. 调参迭代（优先调步数）
5. 沉淀设计记录到 level-design/levels/LXXX.md
```

### 7.3 每关设计检查清单

做完一关后，过一遍这两张清单：

**自我效能感检查（§2.5）：**
- [ ] 玩家过关时，能感知到是自己的决策导致的成功吗？（不是纯运气）
- [ ] 玩家失败时，能想到下次可以怎么做不同吗？（失败可归因）
- [ ] 这关的挑战是否建立在之前某关教过的策略之上？（渐进性）
- [ ] 难度是否在"努力一下就能够到"的范围内？（不打击信念）

**设计者契约检查（§2.6）：**
- [ ] 这关有合理的可发现策略吗？（公平）
- [ ] 所有元素行为与之前一致吗？（一致）
- [ ] 难度与玩家当前信任余额匹配吗？（尊重）
- [ ] 视觉线索诚实吗？如果正解是"先清底部"，底部是否有吸引注意力的视觉暗示？（诚实）

## 8. 做关必知（踩坑经验）

| 经验 | 详情 |
|------|------|
| grid:null 崩溃 | 非 8x8 关卡必须提供显式 Grid 数组 |
| Cage 目标 0% | Cage 只能作为观察元素，不能作为胜利条件 |
| Ice 跳变 | Ice 目标 10→11 有 ~15% 胜率断崖 |
| 步数精度 | ±1 步 ≈ ±3-5% 胜率，是最精准的调参旋钮 |
| Cage 中部死锁 | 4 Cage 交错放中间 → 14.8% 死锁；底部放 → 正常 |
| Spawner 设计 | 只帮不害，seed 粗调 + SpawnModel 安全网（80/20） |
