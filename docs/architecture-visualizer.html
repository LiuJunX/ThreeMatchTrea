核心设计原则

✦ 状态与行为分离 — System 无状态，State 无逻辑
✦ View 无状态投影 — 每帧比对渲染器真实状态
✦ 确定性仿真 — IRandom + FixedDeltaTime = 可回放
✦ AI 零开销 — NullEventCollector + Clone 并行
✦ 事件溯源 — 所有状态变更产生 GameEvent 流
一次 Tick 的完整数据流 16ms

从玩家输入到屏幕渲染，数据单向流动，任何阶段都可分支给 AI

AI 分支：SimulationEngine.Clone()

① Clone()
创建独立引擎副本，GameState 深拷贝，IRandom 独立实例，NullEventCollector（零分配）
② RunUntilStable()
高速仿真到稳定态（无动画延迟），可设 SimulationConfig.ForAI()，100ms step
③ 并行 Best-of-N
多个候选 Move 各自 Clone 并行执行，ThreadLocal Pool 保证线程安全
④ DifficultyAnalysis
有效步数、得分潜力、连消深度、棋盘健康度指标

uint[] (ref-count)
表演同步用。格被动画占用时加锁，防止物理提前处理。
RefCount Choreography

索引规则 & 坐标系

// 1D 索引
int idx = y * Width + x;
var tile = state.Grid[idx];
坐标系
· Grid: (0,0) = 左上角
· Unity: Y轴翻转（View层处理）
· Position struct: int X, int Y
· Vector2: float 连续物理位置
性能特性
· struct 值类型 → 无 GC 压力
· ref/in 传递 → 零拷贝
· 并行数组 → 缓存友好
· 热路径禁 new List → 用 Pool

设计模式汇总

项目中实际应用的模式，每个都有具体的代码映射

架构模式
ECS (精简特化版)
Entity-Component-System 思想。系统无状态，状态集中在 GameState。
State: GameState (SoA arrays)
Systems: IPhysicsSimulation, IMatchFinder...
Entity: Tile.Id (uint)
架构模式
Event Sourcing
所有状态变更产生不可变事件流，可重放，可分析。
Events: GameEvent records (17种)
Collector: IEventCollector
AI优化: NullEventCollector (零分配)
设计模式
Visitor (事件分发)
编译期穷举所有事件类型，替代 switch，新事件不加处理则编译报错。
接口: IEventVisitor (17个Visit方法)
实现: Choreographer
调用: event.Accept(visitor)
设计模式
Command + Replay
玩家操作封装为 Command 对象，支持录制与确定性回放。
接口: IGameCommand
实现: SwapCommand, TapCommand
回放: ReplayController + GameRecording
设计模式
Strategy (炸弹效果)
每种炸弹实现 IBombEffect，通过 BombEffectRegistry 注册。
接口: IBombEffect
策略: HRocketEffect, ColorBombEffect...
注册表: BombEffectRegistry
设计模式
Builder + Factory
Fluent API 组装 13+ Systems，隐藏复杂装配逻辑。
Builder: GameServiceBuilder
Factory: GameServiceFactory
产出: GameSession (完整会话)
数据模式
Data-Oriented Design
SoA 并行数组，struct 值类型，ref/in 传递，缓存友好零GC。
布局: Tile[], Cover[], Ground[] 并行
传递: ref GameState / in GameState
池化: Pools.ObtainList<T>()
架构模式
Immediate Mode View
View 是 VisualState 无状态投影，每帧比对渲染器实际状态，结构性消除 desync。
View: TileView.UpdateFromVisual()
状态源: VisualState (唯一真源)
对比: renderer.sharedMesh != target
性能模式
Null Object (AI优化)
AI 路径使用 NullEventCollector，完全消除事件分配和处理开销。
接口: IEventCollector
AI实现: NullEventCollector.Instance
人类实现: BufferedEventCollector
性能模式
Object Pool
热路径复用集合对象，避免 GC spike（60fps 保障）。
获取: Pools.ObtainList<T>()
释放: Pools.Release(obj) 在 finally
线程: ThreadLocal 实现，Clone安全
架构模式
Dependency Injection
所有 System 通过构造函数注入，零框架依赖，可测试性极高。
容器: GameServiceBuilder (手工DI)
注入点: SimulationEngine 构造函数
测试: 任意 System 可独立 mock
数据模式
Deterministic Simulation
固定时间步长 + 种子化随机 + Command录制 = 完全可重现。
时钟: FixedDeltaTime = 0.016s
随机: IRandom (禁用 System.Random)
种子: SeedManager 多域隔离
